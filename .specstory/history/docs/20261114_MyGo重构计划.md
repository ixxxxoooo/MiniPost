# MiniPost → MyGo 重构计划

> 作者：ixxxxoooo ｜ 日期：2026-11-14 ｜ 分支：`refactor/mygo-migration`
> 依据：MyGo 0.9.0 文档（https://mygo.run/docs ，原 mygo.egoist.dev 已 308 跳转至此）与当前 `main`（1c4f106）代码盘点。
> 标注 **【待验证】** 的条目来自文档未写明之处，须在阶段 0 用原型确认，不能当作既定事实。

## 1. 目标与边界

| 项 | 结论 |
|---|---|
| 目标 | 把桌面外壳从 Wails v2 整体换成 MyGo，一次性换完，不保留 Wails 双轨 |
| 硬约束 | 所有 UI、交互、快捷键、数据格式**保持原样**；本轮不做任何视觉或功能改动 |
| 路线 | 采用 MyGo 的 **Web 前端模式**（系统 WebView + 类型化 IPC），React 前端原样保留 |
| 不采用 | MyGo 原生 UI 模式（纯 Go 绘制）。它需要重写 1.8 万行 React 并替换 Monaco，无法满足"UI 不变"，留作后续独立议题 |
| 不动 | `internal/` 下的 model / service / repository / pkg（约 6000 行）与其测试；`~/.minipost` 数据目录与文件格式 |

改动面其实很集中：Go 侧只有 `main.go`、`main_bindings.go`、`app.go` 中的 6 处 Wails runtime 调用；前端有 21 个文件引用 `wailsjs/`；其余是构建脚本、CI 和文档。

## 3. 目标架构

```
MiniPost/
├── main.go                 入口：日志 → 绑定 → WhenReady 建窗口 → Run
├── app.go                  App 结构体与构造、生命周期（≤300 行）
├── app_http.go             发送 / 流式 / 取消
├── app_collection.go       项目、文件夹、请求、环境、历史
├── app_import.go           导入导出与预览
├── app_dialog.go           文件对话框、保存文件
├── app_window.go           退出、剪贴板等外壳能力（视 4.3 验证结果）
├── events.go               mygo.NewEvent 声明
├── backup.go               不变（按 300 行规则拆出 backup_archive.go）
├── internal/               不变
├── mygo.config.ts          取代 wails.json 与 build/ 下的模板
├── resources/icon.png      由 build/appicon.png 迁入
└── frontend/
    └── src/
        ├── mygo.ts         生成文件，不手改，不提交与否见 6.2
        └── bridge/         唯一允许 import mygo.ts 与 mygo-runtime 的目录
            ├── api.ts      后端方法封装（保持现有函数名）
            ├── types.ts    类型再导出（保持 model.* 写法可用）
            ├── window.ts   窗口控制
            ├── events.ts   流式事件订阅
            └── clipboard.ts
```

设计要点：

1. **只绑定一个服务 `App`**。拆文件但不拆服务，前端调用面不变，降低回归面。拆成多服务留到重构完成之后。
2. **前端加一层 `bridge/`**。业务组件只认 `bridge`，不直接碰生成代码。这样 21 个文件的改动只是换 import 路径，函数名与类型名都不变，也便于在 vitest 里整体 mock。
3. **前端目录保持 `frontend/`、包管理器保持 npm**。MyGo 的 `bindings` 默认规则识别 `frontend/package.json`；`devCommand` / `buildCommand` 可以是任意命令。配置文件在无 Bun 时由 Node ≥ 22.6 执行（本机 Node 26）。
4. **初始化后移**。`mygo generate` 会真实运行 `main` 直到 `App.Run`，所以 `NewApp()` 里的存储初始化与日志落盘要放进 `WhenReady`，或在检测到 `MYGO_GENERATE` 时跳过，避免生成绑定时写用户数据目录。

`mygo.config.ts` 草案：

```ts
import { defineConfig } from "mygo-cli"

export default defineConfig({
  name: "MiniPost",
  identifier: "com.wails.MiniPost",          // 见 5.1，保持不变以沿用 WebView 数据
  version: process.env.VERSION ?? "0.1.0",
  devUrl: "http://localhost:5173",
  devCommand: "npm --prefix frontend run dev",
  buildCommand: "npm --prefix frontend run build",
  frontendDist: "frontend/dist",
  bindings: "frontend/src/mygo.ts",
  out: "build",
  macos: { icon: "build/darwin/appicon.icns" },
  windows: { displayName: "MiniPost" },
})
```

窗口选项草案（对应现 `main.go`）：`Title: "MiniPost"`、`URL: "/"`、`Width: 1280`、`Height: 800`、`MinWidth: 900`、`MinHeight: 600`、`Frameless: true`、`Transparent: true`、`StateKey: "main"`。

## 4. API 映射细则

### 4.1 后端方法

约 50 个导出方法签名全部保留，只是调用名变小驼峰（`SendRequestWithEnv` → `App.sendRequestWithEnv`），由 `bridge/api.ts` 以原名再导出。MyGo 要求参数与返回值可 JSON 编码，返回形态为"无 / 值 / error / 值+error"，现有方法全部满足。

需要注意的差异：

- **并发**：MyGo 每次调用在独立 goroutine 中运行。Wails 同样如此，现有 service 已有锁，但要对 `FileStore` 写路径跑一次 `go test -race`。
- **错误对象**：失败时 Promise 以 `CallError` 拒绝（`message` 为错误文本，`method` 为方法名）。前端 36 处 `catch` 中凡是把错误直接转字符串展示的，显示文案可能多出或少了前缀，须在 `bridge/api.ts` 统一归一化为与现在一致的字符串。
- **指针返回**：`*T` 生成为 `T | null`，现 Wails 模型是 class。前端未使用 `createFrom` / `new model.X`（已 grep 确认），仅作类型用，可平滑替换。

### 4.2 流式事件

现状：Go 端按 `streamId` 广播 `minipost:http-stream`，前端 `EventsOn` 后按 `streamId` 过滤。

方案：阶段 2 先**等价迁移**为类型化事件 `mygo.NewEvent[httpStreamEventPayload]("minipost:http-stream")`，载荷结构不变，前端过滤逻辑不变。事件名含冒号与连字符，生成的 TS 属性名如何映射 **【待验证】**，必要时改名为 `httpStream`（事件名对用户不可见）。

`*mygo.Channel[T]` 是更贴合的模型（每次调用一个通道，前端断开即取消 context，可顺带替换 `CancelHTTPRequest`），但会改动发送与取消的控制流，列为重构完成后的优化项，不在本轮做。

### 4.3 窗口与外壳能力

| 现用 | MyGo 方案 | 状态 |
|---|---|---|
| `WindowMinimise` | `currentWindow.minimize()` | 文档已列 |
| `WindowToggleMaximise` | `currentWindow.maximize()` 配合状态判断，或绑定 Go 方法调 `win.ToggleMaximize()` | 【待验证】前端是否直接有 toggle |
| `Quit`（红灯按钮） | 绑定 Go 方法 `App.Quit()` 调 `mygo.App.Quit()` | 需新增绑定 |
| 窗口尺寸/位置读写 + localStorage 轮询 | 改用 `WindowOptions.StateKey`，删除 `App.tsx` 中约 100 行持久化代码 | 行为等价，且多记住最大化状态 |
| `ClipboardGetText/SetText` | Go 端 `mygo.Clipboard` 经绑定暴露；`lib/clipboard.ts` 已有 `navigator.clipboard` 兜底 | 【待验证】前端运行时是否自带剪贴板 API |
| 拖拽区 CSS | `--app-region: drag / no-drag` | 文档已列 |
| 标题栏双击最大化 | 现为前端自行计时判断，保留 | 需确认 MyGo 不会重复触发 |

### 4.4 文件对话框

6 处调用改为 `mygo.Dialog.Open` / `Save`，标题、默认文件名、过滤器文案逐一照搬。用户取消时现在返回空串且不报错，迁移后保持同样语义。对话框需要在应用就绪后调用，并用 `mygo.CallerWindow(ctx)` 取得父窗口，所以这 6 个方法首参加 `context.Context`（不出现在 TS 签名里）。

## 5. 风险与待决策项

### 5.1 localStorage 数据延续（最高风险）

标签页、Cookie Jar、全部设置、主题、语言、上次项目、当前环境、上传历史都存在 WebView 的 localStorage 里，按**源**隔离。Wails 的源是 `wails://wails.localhost`，MyGo 是 `mygo://localhost/`，换壳后老用户这些状态会全部丢失，表现为"升级后标签和 Cookie 没了、设置被重置"。集合与环境数据在 `~/.minipost`，不受影响。

可选方案：

| 方案 | 做法 | 代价 |
|---|---|---|
| A（推荐） | 发最后一个 Wails 小版本：启动时把 localStorage 全量写到 `~/.minipost/ui-state.json`。MyGo 版首次启动时若 localStorage 为空则从该文件回灌 | 多发一个过渡版本；跳过过渡版直接升级的用户仍会丢 |
| B | 把这些状态改为由 Go 落盘到 `~/.minipost`，不再依赖 localStorage | 最稳，但改动 6 个 store，超出"只换壳"范围 |
| C | 接受丢失，在发布说明里写明 | 零成本，体验差 |

标识符保持 `com.wails.MiniPost` 可以让 WebView 数据目录不变，但解决不了源不同的问题，两件事要分开看。**请确认选哪个方案**；未确认前按 A 排期。

### 5.2 其它风险

| 风险 | 说明 | 处理 |
|---|---|---|
| macOS 编辑快捷键 | WebView 里的 ⌘C/V/X/A/Z 依赖应用菜单中存在"编辑"菜单。Wails 默认带，MyGo 默认菜单内容文档未写明 | 阶段 0 验证；必要时用 `App.SetMenu` 显式建应用菜单与编辑菜单 |
| 无边框窗口 | 边缘缩放、圆角、阴影、透明背景在 MyGo 的 `Frameless + Transparent` 下是否与现在一致 | 阶段 0 原型对照截图；可用 `CornerRadius`、`HideWindowButtons` 调整 |
| 默认右键菜单 | 应用有自绘 `SelectionContextMenu`，生产包不能弹出 WebView 原生菜单 | 阶段 0 验证，必要时前端全局拦截 |

| DMG 授权脚本 | 现 DMG 内含 `Authorize MiniPost.command`，MyGo 生成的 DMG 不会带 | 用 `-skip-dmg` 后沿用现有 DMG 打包段，或改为正式签名公证后去掉该脚本。**需确认** |
| 产物命名 | 现约定 `MiniPost-<version>-<platform>-<arch>` | 构建后在脚本里重命名 |
| Windows WebView2 | 现用 `-webview2 download` 策略 | 确认 MyGo 安装器在缺少 WebView2 Runtime 时的行为【待验证】 |
| Monaco 资源加载 | 自定义协议下 worker 与字体加载路径 | 阶段 0 在生产包里验证编辑器与字体 |
